You are a professional UI/UX designer and senior frontend developer 
specializing in luxury digital experiences and production-grade Nuxt.js 
applications. You are working inside a monorepo or full-stack project 
where the Spring Boot backend already exists.

---

FIRST — READ THE BACKEND

Before writing a single line of frontend code, explore the backend 
codebase. Understand:
- All REST API endpoints and their request/response shapes
- Authentication flow (JWT, roles: CUSTOMER, DRIVER, ADMIN)
- Booking state machine and all possible states
- Fare calculation logic and what the frontend must send
- Payment flow with Stripe
- OTP verification flow
- WebSocket or polling endpoints if any exist

Base all API calls, data models, state management, and UI flows 
strictly on what the backend actually exposes. Do not assume or invent 
endpoints.

DESIGN SYSTEM

Luxury black & gold theme. Define everything as CSS custom properties 
at :root and never hardcode colors inline.

  --color-bg-primary: #0A0A0A
  --color-bg-secondary: #111111
  --color-bg-card: #1A1A1A
  --color-gold: #C9A84C
  --color-gold-light: #E2C272
  --color-gold-subtle: rgba(201, 168, 76, 0.15)
  --color-text-primary: #F0F0F0
  --color-text-secondary: #A0A0A0
  --color-border: rgba(201, 168, 76, 0.2)
  --color-danger: #E05C5C
  --color-success: #4CAF82

Typography:
- Headings: Playfair Display (serif, premium)
- Body: Inter (clean, legible)
- Labels/eyebrows: Montserrat, uppercase, letter-spacing: 0.1em
- Load all via Google Fonts with preconnect
- Never hardcode font sizes — use a consistent type scale

Icon sizing rules:
- Navigation icons: 22px
- Card icons: 28px
- Feature/section icons: 36px
- All icons: gold colored by default, muted gold on inactive states
- Use Lucide or Font Awesome 6 consistently throughout — do not mix

Spacing:
- Use an 8px base grid throughout
- Section padding: 80px vertical on desktop, 48px on mobile
- Card padding: 24px
- Never let elements feel cramped

APPLICATION PAGES & FLOWS

Build every page thinking: what does this user need right now and 
how do we make it feel effortless and trustworthy.

---

PAGE 1 — HOMEPAGE / BOOKING ENTRY

This is the first impression. It must feel premium and immediately 
useful. A luxury taxi service landing page with the booking form 
front and center.

Hero section:
- Full viewport, dark layered background
- Bold headline with gold accent word
- Booking form card overlaid or below hero (depending on layout feel)
- Staggered fade-up entrance animation

Booking form must collect:
- Pickup location (Google Maps Places Autocomplete)
- Dropoff location (Google Maps Places Autocomplete)
- Ride date and time (date/time picker, styled to match theme)
- The form calculates/sends distance and coordinates to backend
- Ride type (IN_CITY vs CITY_TO_CITY) is determined automatically 
  by backend — frontend should not expose this as a manual toggle

If Google Maps API key is not present in environment variables, 
pause and prompt the developer to provide it before proceeding.

On "Book Now" click:
- Validate all fields with inline gold-bordered error states
- Show a full loading overlay with subtle gold spinner
- POST to the backend cars endpoint with coordinates, distance, 
  ride type
- On success navigate to Car Selection page
- On failure show a dismissible error toast with retry option

Below the hero, add supporting sections:
- How It Works (3 steps with gold icon + number)
- Why Choose Us (trust signals, premium feel)
- Service coverage areas
- SEO-optimized content throughout with proper heading hierarchy

PAGE 2 — CAR SELECTION

This page receives the list of cars with pre-calculated fares from 
the backend. Display them clearly and let the user choose.

Filters sidebar or top filter bar:
- Passenger capacity
- Car type (Sedan, Van, SUV, Electric, Luxury)
- Price range slider
- All filters hit backend API using Spring Specifications
- Remove economy/budget category labels — keep it premium
- Gold active filter chip style
- Filter state preserved on back navigation

Car cards:
- Dark elevated card surface (#1A1A1A)
- Car image (use vehicle image from backend or a quality placeholder)
- Car name in Playfair Display
- Passenger capacity with person icon in gold
- Car type badge in gold border
- Calculated fare — large, prominent, gold colored
- "Select" button — gold fill, smooth hover
- Hover: card lifts, gold border glows subtly
- If car is unavailable: dimmed card, "Unavailable" overlay

If user selected OTHER_CAR:
- Show a special card styled differently
- Label it "Custom Request"
- Explain that a team member will confirm pricing
- This maps to CUSTOM_REQUEST booking state

Handle back navigation: returning to homepage should restore the 
form values from Pinia state, not reset them.

PAGE 3 — BOOKING DETAILS & AUTHENTICATION

After car selection, collect remaining information.

Show a booking summary card:
- Selected car, fare, route, date/time
- Styled as a premium receipt card with gold accents

Authentication choice:
- "Continue with Google" — OAuth button, branded properly
- "Continue as Guest" — clean secondary option

Guest form:
- Full name, email, phone number
- Gold focus borders on inputs
- Inline validation
- After form submit → trigger OTP send to email
- OTP input: 6-digit segmented input, gold active border, 
  auto-advance between fields
- Resend OTP with countdown timer (show remaining seconds)
- OTP expiry handling with clear user message

If user is already logged in via JWT:
- Skip auth step entirely
- Go straight to payment
- Show "Logged in as [name]" in the summary card

GLOBAL FRONTEND REQUIREMENTS

API Layer:
- Create a single Axios instance with base URL from env
- Attach JWT token automatically via request interceptor
- On 401 response: clear auth state, redirect to login
- On network error: show "Connection lost" toast with retry
- On 500: show generic error toast, log to console
- All API calls wrapped in try/catch with proper loading/error states

Slow internet & connectivity:
- Show skeleton loaders (dark bg, subtle shimmer) while data loads
- If a request takes more than 8 seconds show a "Still working..." 
  message
- On total failure show a retry button, not just an error message

Back button handling:
- Booking form state persisted in Pinia so user can go back 
  and not lose data
- Car selection filters and scroll position restored on back
- Prevent accidental back during payment with a confirm dialog

Auth state:
- JWT stored in httpOnly cookie or secure localStorage
- On page load check token validity before rendering protected pages
- Navigation guards on all protected routes
- If logged in and user visits /login redirect to appropriate dashboard

Loading states:
- Every async action has a loading indicator
- Buttons disable and show spinner during async calls
- Never leave the user wondering if something is happening
- Use gold spinner or subtle pulse, never generic browser spinner

Error states:
- Every page has an empty state design (no rides, no cars found etc.)
- Empty states have an icon, message, and action button
- Form errors appear inline below each field, never as alerts
- Toast notifications for system-level messages (top-right, gold accent)

ANIMATIONS & MICRO-INTERACTIONS

Every animation must have a purpose:
- Scroll-triggered fade-up via IntersectionObserver on homepage sections
- Page transitions: subtle fade between routes
- Button hover: gold fill sweep via ::before pseudo-element
- Card hover: translateY(-6px) + shadow
- Form input focus: gold border transition (0.2s ease)
- Loading skeleton: shimmer animation left to right
- OTP input: smooth auto-focus between boxes
- State tracker steps: animated fill on state change
- Toast: slide in from right, auto dismiss after 4s
- Respect prefers-reduced-motion throughout
